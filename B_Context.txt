## PROJECT OVERVIEW
This is a comprehensive Node.js/Express backend server for the Yarkib Bike Riding App that serves as an intermediary between frontend applications (web and mobile) and Supabase. The backend handles user authentication (OAuth and email), route management, user interactions with routes, admin panel functionality, and provides a complete RESTful API for the cycling community.

## AUTHENTICATION SYSTEM

### Authentication Flow Types

#### 1. Email Authentication
- **Registration**: POST `/auth/email/signup`
- **Login**: POST `/auth/email/login`
- **Flow**: Email + Password → Supabase Auth → JWT Token

#### 2. OAuth Authentication
- **Providers**: Google, Apple
- **Initiation**: POST `/auth/signin`
- **Callback**: GET `/auth/callback`
- **Flow**: OAuth Provider → Authorization Code → JWT Token

#### 3. Mobile OAuth Authentication
- **Initiation**: POST `/auth/mobile/signin`
- **Callback**: GET `/auth/mobile/callback`
- **Deep Link**: `yarkib://oauth/callback`
- **Flow**: OAuth → ngrok callback → Deep link redirect

### JWT Token Structure
- **Header**: `Authorization: Bearer <jwt_token>`
- **Token Source**: Supabase Auth
- **Validation**: `supabase.auth.getUser(token)`
- **Expiration**: Handled by Supabase

### Authentication Middleware
```javascript
const authenticateUser = async (req, res, next) => {
  try {
    const authHeader = req.headers.authorization;
    if (!authHeader || !authHeader.startsWith('Bearer ')) {
      return res.status(401).json({ error: 'Missing or invalid authorization header' });
    }
    
    const token = authHeader.substring(7);
    const { data: { user }, error } = await supabase.auth.getUser(token);
    
    if (error) throw error;
    
    req.user = user;
    next();
  } catch (error) {
    res.status(401).json({ error: error.message });
  }
};
```

### Admin Authentication Middleware
```javascript
const isAdmin = async (req, res, next) => {
  try {
    // ... user authentication ...
    
    // Check admin role in admins table
    const { data: adminData, error: adminError } = await supabase
      .from('admins')
      .select('id')
      .eq('user_id', user.id)
      .single();
    
    if (adminError || !adminData) {
      return res.status(403).json({ error: 'Unauthorized: Admin access required' });
    }
    
    req.user = user;
    next();
  } catch (error) {
    res.status(401).json({ error: error.message });
  }
};
```

- **Group Ride Endpoints**: No JWT; `user_id` passed from client

## GROUP RIDE SYSTEM

### Overview
The group ride system enables collaborative cycling experiences where users can create group rides, invite other users, and manage group participation through a comprehensive invitation and notification system.

### Group Ride Flow
1. **Create Group Ride**: User creates a group ride for a specific route
2. **Auto-Membership**: Creator automatically becomes leader member
3. **Invite Users**: Members can invite others by username
4. **Notification System**: Invited users receive notifications
5. **Accept/Reject**: Users can accept or reject invitations
6. **Join Group**: Accepted users become group members
7. **Group Management**: Leader can cancel, members can leave

### Key Features
- **Username-based Invitations**: Users are identified by unique usernames
- **Role-based Access**: Leaders (creators) vs Members distinction
- **Status Tracking**: Active, Completed, Cancelled states
- **Notification System**: Real-time notifications for all group activities
- **Pagination Support**: All list endpoints support pagination
- **Comprehensive Validation**: UUID validation, existence checks, permission verification

### Group Ride States
- **active**: Group ride is ongoing and accepting members
- **completed**: Group ride has finished successfully
- **cancelled**: Group ride was cancelled by the creator

### Member Roles
- **leader**: Group ride creator, can cancel group rides
- **member**: Regular participants, can leave but not cancel

### Notification Types
- **group_ride_invitation**: User invited to join group ride
- **group_ride_accepted**: Invitation accepted by user
- **group_ride_rejected**: Invitation rejected by user
- **group_ride_cancelled**: Group ride cancelled by creator

### Data Relationships
- **group_rides** → **routes**: Each group ride is based on a route
- **group_rides** → **profiles**: Creator reference
- **group_ride_members** → **group_rides**: Membership tracking
- **group_ride_members** → **profiles**: Member reference
- **group_ride_invitations** → **group_rides**: Invitation tracking
- **group_ride_invitations** → **profiles**: Sender/receiver references
- **notifications** → **profiles**: User notification system

### Common Query Patterns

#### 1. Basic Select with Pagination
```javascript
const { data, error } = await supabase
  .from('routes')
  .select('*, categories(name, icon)')
  .range(offset, offset + limit - 1)
  .order('created_at', { ascending: false });
```

#### 2. Filtered Queries
```javascript
let query = supabase.from('routes').select('*, categories(name, icon)');

if (category_id) {
  query = query.eq('category_id', category_id);
}

if (search) {
  query = query.ilike('name', `%${search}%`);
}
```

#### 3. Count Queries for Pagination
```javascript
const { count, error: countError } = await supabase
  .from('routes')
  .select('id', { count: 'exact' });
```

#### 4. Insert Operations
```javascript

  .from('routes')
```

## MOBILE OAUTH FLOW DETAILS

### Mobile OAuth Process
1. **Initiation**: Mobile app calls `/auth/mobile/signin`
2. **OAuth URL**: Backend generates OAuth URL with ngrok callback
3. **User Authentication**: User authenticates with Google/Apple
4. **Callback**: Google/Apple redirects to ngrok URL
5. **Token Exchange**: Backend exchanges code for session
6. **Deep Link**: Backend redirects to mobile app deep link
7. **Session Data**: Mobile app receives session via deep link

### Deep Link Format
```
yarkib://oauth/callback?session=<encoded_session_data>
yarkib://oauth/callback?error=<encoded_error_message>
```

## TROUBLESHOOTING GUIDE

### Common Issues

#### 1. OAuth Callback Failures
- **Symptom**: Users can't complete OAuth login
- **Cause**: ngrok URL not accessible or expired
- **Solution**: Update ngrok URL and restart server

#### 2. Database Connection Issues
- **Symptom**: 500 errors on database operations
- **Cause**: Invalid Supabase credentials or network issues
- **Solution**: Verify environment variables and network connectivity

#### 3. JWT Token Validation Failures
- **Symptom**: 401 errors on authenticated endpoints
- **Cause**: Expired or invalid tokens
- **Solution**: Implement token refresh mechanism

#### 4. Mobile Deep Link Issues
- **Symptom**: Mobile app doesn't receive OAuth data
- **Cause**: Deep link scheme not properly configured
- **Solution**: Verify deep link configuration in mobile app

#### 5. File Upload Failures
- **Symptom**: Image uploads fail with 500 errors
- **Cause**: Supabase Storage permissions or bucket issues
- **Solution**: Check Storage bucket permissions and policies

### Database Schema Reference
```sql
-- User Routes Table
CREATE TABLE public.user_routes (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  route_id uuid NOT NULL REFERENCES public.routes(id) ON DELETE CASCADE,
  status character varying NOT NULL CHECK (status IN ('saved','completed')),
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  CONSTRAINT user_routes_unique_user_route_status UNIQUE (user_id, route_id, status)
);

-- Group Ride Tables
-- Add username to profiles table
ALTER TABLE public.profiles
ADD COLUMN username varchar UNIQUE;

-- Group Rides Table (parent entity)
CREATE TABLE public.group_rides (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  route_id uuid NOT NULL REFERENCES public.routes(id),
  created_by uuid NOT NULL REFERENCES public.profiles(id),
  status varchar NOT NULL CHECK (status IN ('active', 'completed', 'cancelled')),
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  CONSTRAINT group_rides_pkey PRIMARY KEY (id)
);

-- Group Ride Members Table
CREATE TABLE public.group_ride_members (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  group_ride_id uuid NOT NULL REFERENCES public.group_rides(id) ON DELETE CASCADE,
  user_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  role varchar CHECK (role IN ('leader', 'member')) DEFAULT 'member',
  joined_at timestamp with time zone DEFAULT now(),
  CONSTRAINT group_ride_members_pkey PRIMARY KEY (id),
  CONSTRAINT group_ride_members_unique_user_group UNIQUE (group_ride_id, user_id)
);

-- Group Ride Invitations Table
CREATE TABLE public.group_ride_invitations (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  group_ride_id uuid NOT NULL REFERENCES public.group_rides(id) ON DELETE CASCADE,
  sender_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  receiver_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  status varchar NOT NULL CHECK (status IN ('pending', 'accepted', 'rejected')),
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  CONSTRAINT group_ride_invitations_pkey PRIMARY KEY (id),
  CONSTRAINT group_ride_invitations_unique_group_receiver UNIQUE (group_ride_id, receiver_id)
);

-- Notifications Table
CREATE TABLE public.notifications (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  type varchar NOT NULL,
  message text,
  related_id uuid,
  is_read boolean DEFAULT false,
  created_at timestamp with time zone DEFAULT now(),
  CONSTRAINT notifications_pkey PRIMARY KEY (id)
);
```
